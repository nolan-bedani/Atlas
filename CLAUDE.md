# Règles de développement - Projet Helpdesk Atlas (PRA/DR)## Contexte du projet*   **Objectif :** Déploiement d'un portail de tickets interne GLPI-like  .*   **Contraintes de reprise :** RPO <= 20 minutes, RTO <= 40 minutes[cite: 1].*   **Méthodologie :** Infrastructure as Code (IaC) et scripts obligatoires. Aucun "clic-clic" manuel non tracé n'est autorisé[cite: 1].## Architecture & Stack Technique*   **Web/App :** Nginx/Apache + PHP (LAMP)[cite: 1].*   **Base de données :** MariaDB/MySQL[cite: 1].*   **Reverse Proxy :** Nginx avec chiffrement TLS obligatoire[cite: 1].*   **Supervision :** Zabbix (Agents, checks HTTP, DB)[cite: 1].*   **Réseau :** DMZ (VLAN 20 - 10.20.0.0/24), LAN ADMIN (VLAN 30 - 10.30.0.0/24), MGMT (VLAN 90)[cite: 1].## Règles de Sécurité Strictes*   **Secrets :** Les mots de passe, certificats TLS et configurations sensibles doivent rester HORS du gestionnaire de version (VCS)[cite: 1]. Utilise des variables d'environnement.*   **Privilèges :** Utilise toujours le principe du moindre privilège pour les comptes de service[cite: 1]. Aucun compte administrateur par défaut ne doit être conservé[cite: 1].## Commandes et Livrables*   Génère les scripts sous forme de code bash, Ansible ou Docker Compose selon les besoins.*   Documente chaque script en Markdown pour alimenter le Dossier d'Architecture Technique (DAT) et les Runbooks[cite: 1].
